# REST API: электронная библиотека

## 1. Контракт API

Базовый URL: `/api/v1`. Все защищённые операции используют `Authorization: Bearer <JWT>`.

| Метод | URI | Назначение | Роль | Успешный ответ |
|---|---|---|---|---|
| POST | `/auth/register` | Регистрация читателя | Все | 201 Created |
| POST | `/auth/login` | Получение JWT | Все | 200 OK |
| GET | `/books` | Поиск и постраничный список книг | Все | 200 OK |
| POST | `/books` | Создание книги и экземпляров | Библиотекарь | 201 Created |
| GET | `/books/{bookId}` | Карточка книги и доступность | Все | 200 OK |
| POST | `/reservations` | Бронирование экземпляра | Читатель | 201 Created |
| GET | `/me/reservations` | Брони текущего читателя | Читатель | 200 OK |
| DELETE | `/reservations/{reservationId}` | Отмена брони | Владелец/библиотекарь | 204 No Content |
| POST | `/loans` | Выдача книги по брони | Библиотекарь | 201 Created |
| GET | `/me/loans` | История и активные выдачи | Читатель | 200 OK |
| POST | `/loans/{loanId}/return` | Возврат книги | Библиотекарь | 200 OK |
| GET | `/fines` | Просмотр штрафов | Библиотекарь | 200 OK |
| GET | `/health` | Проверка доступности сервиса | Все | 200 OK |

### Правила HTTP

- `400 Bad Request` — ошибка формата или бизнес-валидации тела запроса.
- `401 Unauthorized` — отсутствует или недействителен JWT.
- `403 Forbidden` — пользователь вошёл, но не имеет нужной роли.
- `404 Not Found` — ресурс не найден или недоступен пользователю.
- `409 Conflict` — экземпляр уже забронирован/выдан или нарушено состояние ресурса.
- `422 Unprocessable Entity` — корректный JSON с ошибкой предметной области.
- `500 Internal Server Error` — необработанная ошибка сервера.

## 2. Use Cases API

Сценарий «забронировать книгу» выполняется так: читатель получает список книг, выбирает доступный `copyId`, отправляет `POST /reservations`; сервер в транзакции проверяет блокировку пользователя и уникальность активной брони, создаёт бронь на 48 часов и возвращает `201`.

Сценарий «выдать книгу» доступен библиотекарю: `POST /loans` проверяет активную бронь, переводит экземпляр в `loaned`, создаёт выдачу на 30 дней и закрывает бронь как `fulfilled`. При возврате сервер вычисляет просрочку и создаёт штраф, если срок нарушен.

## 3. Ответы на контрольные вопросы

1. **Query, Path и Request Body.** Query-параметры фильтруют коллекцию и не идентифицируют конкретный ресурс: `/books?author=...&page=2`. Path-параметр адресует один ресурс: `/books/{bookId}`. Request Body передаёт структурированные данные для создания или изменения ресурса; его нельзя заменять query-параметрами, если данные сложные или чувствительные.
2. **Идемпотентность.** Повтор идемпотентного запроса оставляет ресурс в том же состоянии: `GET`, `PUT` и `DELETE` при одинаковых параметрах дают тот же итог. `POST` обычно создаёт новый ресурс при каждом повторе, поэтому не считается идемпотентным; для безопасных повторов применяют `Idempotency-Key`.
3. **401 и 403.** `401 Unauthorized` означает, что клиент не прошёл аутентификацию: токен отсутствует, истёк или неверен. `403 Forbidden` означает, что личность установлена, но доступ запрещён, например читатель вызывает административный endpoint.
4. **components/schemas и `$ref`.** В `components/schemas` хранятся переиспользуемые модели запросов и ответов. `$ref` подключает модель по ссылке, поэтому один источник описания используется во многих endpoint’ах и не расходится при изменениях.
5. **PUT и PATCH.** `PUT` заменяет ресурс целиком и должен быть идемпотентным; клиент передаёт полное представление. `PATCH` изменяет отдельные поля, поэтому подходит для частичного обновления профиля или статуса.
